使用 MCP 执行代码：构建更高效的智能体

发布于 2025 年 11 月 4 日

直接工具调用会为每项定义和结果消耗上下文。智能体改为编写代码调用工具，扩展性更好。以下介绍它如何与 MCP 配合。

非官方中文译文，仅供个人或获授权的内部阅读。 查看英文原文

模型上下文协议（MCP）是一项将 AI 智能体连接至外部系统的开放标准。传统上，将智能体连接到工具和数据，需要为每种配对建立定制集成，造成碎片化和重复工作，难以扩展真正互联的系统。MCP 提供通用协议——开发者只需在智能体中实现一次 MCP，便可解锁整个集成生态。

自 2024 年 11 月推出 MCP 以来，其采用极为迅速：社区已构建数千个 MCP 服务器, 各主流编程语言均提供 SDK，行业也已将 MCP 采纳为把智能体连接至工具和数据的事实标准。

如今，开发者经常构建可访问数十个 MCP 服务器中数百或数千项工具的智能体。然而，随着连接工具数量增长，预先加载全部工具定义并通过上下文窗口传递中间结果，会拖慢智能体并增加成本。

本文将探索代码执行如何让智能体更高效地与 MCP 服务器交互：处理更多工具的同时使用更少 token。

工具造成的过量 token 消耗会降低智能体效率

随着 MCP 使用规模扩大，有两种常见模式会增加智能体成本和延迟：

  1. 工具定义挤占上下文窗口；
  2. 中间工具结果消耗额外 token。

1. 工具定义挤占上下文窗口

大多数 MCP 客户端将全部工具定义直接预加载到上下文中，并通过直接工具调用语法向模型暴露。工具定义可能如下：

gdrive.getDocument
     Description: Retrieves a document from Google Drive
     Parameters:
                documentId (required, string): The ID of the document to retrieve
                fields (optional, string): Specific fields to return
     Returns: Document object with title, body content, metadata, permissions, etc.
salesforce.updateRecord
    Description: Updates a record in Salesforce
    Parameters:
               objectType (required, string): Type of Salesforce object (Lead, Contact,      Account, etc.)
               recordId (required, string): The ID of the record to update
               data (required, object): Fields to update with their new values
     Returns: Updated record object with confirmation

工具说明占据更多上下文窗口空间，从而增加响应时间和成本。当智能体连接数千个工具时，在读取一个请求前可能就需处理数十万个 token。

2. 中间工具结果消耗额外 token

大多数 MCP 客户端允许模型直接调用 MCP 工具。例如，你可能会要求智能体：“从 Google Drive 下载我的会议记录，并将其附加到 Salesforce 线索。”

模型会作出如下调用：

TOOL CALL: gdrive.getDocument(documentId: "abc123")
        → returns "Discussed Q4 goals...\n[full transcript text]"
           (loaded into model context)

TOOL CALL: salesforce.updateRecord(
			objectType: "SalesMeeting",
			recordId: "00Q5f000001abcXYZ",
  			data: { "Notes": "Discussed Q4 goals...\n[full transcript text written out]" }
		)
		(model needs to write entire transcript into context again)

每个中间结果都必须经过模型。在此例中，完整会议记录会流经模型两次。对于一场两小时销售会议，这可能意味着额外处理 50,000 token。更大的文档甚至可能超出上下文窗口限制，从而使工作流中断。

处理大型文档或复杂数据结构时，模型在工具调用之间复制数据也更容易出错。

通过 MCP 执行代码提升上下文效率

随着代码执行环境在智能体中更常见，一种解决方法是将 MCP 服务器呈现为代码 API，而非直接工具调用。智能体便可编写代码与 MCP 服务器交互。该方法同时解决两个挑战：智能体仅加载所需工具，并在将结果传回模型前在执行环境中处理数据。

实现方式不止一种。一个方法是从已连接 MCP 服务器的全部可用工具生成文件树。以下是使用 TypeScript 的实现：

servers
├── google-drive
│   ├── getDocument.ts
│   ├── ... (other tools)
│   └── index.ts
├── salesforce
│   ├── updateRecord.ts
│   ├── ... (other tools)
│   └── index.ts
└── ... (other servers)

随后，每项工具都对应一个文件，例如：

// ./servers/google-drive/getDocument.ts
import { callMCPTool } from "../../../client.js";

interface GetDocumentInput {
  documentId: string;
}

interface GetDocumentResponse {
  content: string;
}

/* Read a document from Google Drive */
export async function getDocument(input: GetDocumentInput): Promise<GetDocumentResponse> {
  return callMCPTool<GetDocumentResponse>('google_drive__get_document', input);
}

上文 Google Drive 到 Salesforce 的示例会变成以下代码：

// Read transcript from Google Docs and add to Salesforce prospect
import * as gdrive from './servers/google-drive';
import * as salesforce from './servers/salesforce';

const transcript = (await gdrive.getDocument({ documentId: 'abc123' })).content;
await salesforce.updateRecord({
  objectType: 'SalesMeeting',
  recordId: '00Q5f000001abcXYZ',
  data: { Notes: transcript }
});

智能体通过探索文件系统发现工具：列出 ./servers/ 目录以查找可用服务器（如 google-drive 和 salesforce），然后读取所需的具体工具文件（如 getDocument.ts 和 updateRecord.ts）以理解每项工具接口。这让智能体只加载当前任务所需定义，将 token 使用量从 150,000 降到 2,000，节省 98.7% 的时间与成本。.

Cloudflare 发布过类似发现，将 MCP 的代码执行称为“代码模式（Code Mode）”。核心洞见相同：LLM 擅长编写代码，开发者应利用这一优势，构建能更高效与 MCP 服务器交互的智能体。

通过 MCP 执行代码的益处

通过 MCP 执行代码可让智能体按需加载工具、在数据到达模型前筛选数据，并在一步中执行复杂逻辑，因而更高效地使用上下文。该方法还带来安全性和状态管理方面的好处。

渐进式披露

模型擅长浏览文件系统。将工具以文件系统中的代码形式呈现，可让模型按需读取工具定义，而非预先读取全部定义。

或者，可向服务器添加一个 search_tools 工具以查找相关定义。例如，使用上文假设的 Salesforce 服务器时，智能体搜索“salesforce”，只加载当前任务需要的工具。在 search_tools 工具中加入详情级别参数，使智能体可选择所需详情程度（如仅名称、名称与说明，或包含模式的完整定义），也有助于智能体节省上下文并高效找到工具。

上下文高效的工具结果

处理大型数据集时，智能体可在返回结果前用代码筛选和转换。设想抓取一份 10,000 行电子表格：

// Without code execution - all rows flow through context
TOOL CALL: gdrive.getSheet(sheetId: 'abc123')
        → returns 10,000 rows in context to filter manually

// With code execution - filter in the execution environment
const allRows = await gdrive.getSheet({ sheetId: 'abc123' });
const pendingOrders = allRows.filter(row => 
  row["Status"] === 'pending'
);
console.log(`Found ${pendingOrders.length} pending orders`);
console.log(pendingOrders.slice(0, 5)); // Only log first 5 for review

智能体只看到 5 行而非 10,000 行。类似模式可用于聚合、跨多个数据源连接，或提取特定字段——且不会使上下文窗口膨胀。

更强大且上下文高效的控制流

循环、条件与错误处理可用熟悉的代码模式完成，而无需串接各个工具调用。例如，如需在 Slack 中发送部署通知，智能体可写：

let found = false;
while (!found) {
  const messages = await slack.getChannelHistory({ channel: 'C123456' });
  found = messages.some(m => m.text.includes('deployment complete'));
  if (!found) await new Promise(r => setTimeout(r, 5000));
}
console.log('Deployment notification received');

这种方法比在智能体循环中交替进行 MCP 工具调用和 sleep 命令更高效。

此外，能够写出并执行条件树也能节省“首 token 时间”延迟：智能体不必等待模型求值 if 语句，而可让代码执行环境完成此事。

保护隐私的操作

当智能体使用 MCP 执行代码时，中间结果默认留在执行环境中。这样，智能体只会看到你明确记录或返回的内容；不希望与模型共享的数据可流经工作流，却永不进入模型上下文。

对于更敏感的工作负载，智能体 harness 可自动将敏感数据 token 化。例如，假设你需要将电子表格中的客户联系方式导入 Salesforce，智能体会写：

const sheet = await gdrive.getSheet({ sheetId: 'abc123' });
for (const row of sheet.rows) {
  await salesforce.updateRecord({
    objectType: 'Lead',
    recordId: row.salesforceId,
    data: { 
      Email: row.email,
      Phone: row.phone,
      Name: row.name
    }
  });
}
console.log(`Updated ${sheet.rows.length} leads`);

MCP 客户端会在数据到达模型前拦截数据并将 PII token 化：

// What the agent would see, if it logged the sheet.rows:
[
  { salesforceId: '00Q...', email: '[EMAIL_1]', phone: '[PHONE_1]', name: '[NAME_1]' },
  { salesforceId: '00Q...', email: '[EMAIL_2]', phone: '[PHONE_2]', name: '[NAME_2]' },
  ...
]

随后，当数据在另一次 MCP 工具调用中共享时，MCP 客户端会通过查找将其反 token 化。真实电子邮件地址、电话号码和姓名从 Google Sheets 流向 Salesforce，却从不经过模型。这能防止智能体意外记录或处理敏感数据。你也可借此定义确定性安全规则，选择数据可流向何处、来自何处。

状态持久化与技能

具备文件系统访问能力的代码执行，可让智能体跨操作维持状态。智能体可将中间结果写入文件，从而恢复工作并追踪进度：

const leads = await salesforce.query({ 
  query: 'SELECT Id, Email FROM Lead LIMIT 1000' 
});
const csvData = leads.map(l => `${l.Id},${l.Email}`).join('\n');
await fs.writeFile('./workspace/leads.csv', csvData);

// Later execution picks up where it left off
const saved = await fs.readFile('./workspace/leads.csv', 'utf-8');

智能体还可将自己的代码持久化为可复用函数。一旦智能体为任务开发出可用代码，便可保存实现以供未来使用：

// In ./skills/save-sheet-as-csv.ts
import * as gdrive from './servers/google-drive';
export async function saveSheetAsCsv(sheetId: string) {
  const data = await gdrive.getSheet({ sheetId });
  const csv = data.map(row => row.join(',')).join('\n');
  await fs.writeFile(`./workspace/sheet-${sheetId}.csv`, csv);
  return `./workspace/sheet-${sheetId}.csv`;
}

// Later, in any agent execution:
import { saveSheetAsCsv } from './skills/save-sheet-as-csv';
const csvPath = await saveSheetAsCsv('abc123');

这与 技能 的概念密切相关：它们是包含可复用说明、脚本和资源的文件夹，可让模型在专业任务上提升性能。为这些保存函数添加 SKILL.md 文件，便创建出模型可以参考和使用的结构化技能。随着时间推移，这使智能体能建立一套更高层能力工具箱，演进其最有效工作所需的脚手架。

请注意，代码执行本身会引入复杂性。运行智能体生成的代码需要具备适当 沙箱化、资源限制和监控的安全执行环境。这些基础设施要求增加了直接工具调用所避免的运营开销和安全考量。应当权衡代码执行带来的好处——降低 token 成本、减少延迟和提升工具组合能力——与这些实现成本。

总结

MCP 为智能体连接许多工具和系统提供基础协议。然而，连接过多服务器后，工具定义和结果会消耗过量 token，降低智能体效率。

虽然此处的许多问题——上下文管理、工具组合、状态持久化——似乎很新颖，软件工程中已有已知解决方案。代码执行将这些成熟模式应用于智能体，使其能使用熟悉的编程构造与 MCP 服务器更高效交互。如果你实现此方法，我们鼓励你与 MCP 社区.
